## Возможности

Всё считается **локально** — тяжёлые операции (кодирование, ИИ-модели, апскейл) не уходят на сторонние серверы.

| | |
|---|---|
| 🎬 **Конвертер и сжатие** | Видео/аудио/изображения через локальный FFmpeg, матрица энкодеров (x264/x265/AV1, NVENC) |
| 📄 **PDF-тулкит** | Слияние, разбиение, поворот, водяной знак, номера страниц, сборка из изображений, извлечение текста, Word/PowerPoint/Excel ⇄ PDF (через уже установленный MS Office или LibreOffice) |
| ⬇️ **Загрузчик и музыка** | yt-dlp «из коробки» — видео и аудио с YouTube и других сайтов |
| 🍿 **Фильмы и сериалы** | Каталог TMDB, свои закладки (папки), отметки прогресса по сезонам/сериям, оценки и статистика, поиск раздач на трекерах, встроенный торрент-плеер |

| ⚡ **Автоматизация** | Быстрый лаунчер программ/скриптов + запуск по расписанию через Планировщик заданий Windows |

Плюс: 5 тем оформления, 6 акцентных цветов, адаптивный интерфейс под узкие окна, стартовый экран с обзором возможностей (отключаемый в настройках).

## Установка

1. Скачайте `MoonApp-Setup-x.y.z.exe` со страницы **[Releases](https://github.com/NoonLicht/MoonApp/releases/latest)**.
2. Запустите — установка не требует прав администратора.
3. Рядом с программой появится папка `storage\` со всеми данными.

> Windows SmartScreen может предупредить о неизвестном издателе (сборка ещё не подписана
> сертификатом) — «Подробнее» → «Выполнить в любом случае».

Приложение само проверяет обновления и предлагает установить новую версию, не трогая `storage`.

## Запуск из исходников

Требуется **Node.js ≥ 20**.

```bash
git clone https://github.com/NoonLicht/MoonApp.git
cd MoonApp
npm install
npm run rebuild:electron   # пересборка better-sqlite3 под Electron
npm start                  # сборка web-части + запуск приложения
```

| Скрипт | Назначение |
|---|---|
| `npm run dev` | Только Vite dev-сервер (фронт на `:5173`, API проксируется на `:4000`) |
| `npm run start:server` | Только Express-сервер без UI (`:4000`) |
| `npm run compile` | Сборка TS-исходников: `server/ts → server`, `electron/ts → electron`, `scripts/ts → scripts` (артефакты в git не хранятся) |
| `npm run typecheck` | Проверка типов (фронт) + компиляция server/electron/scripts |
| `npm run check:i18n` | Полнота переводов: одинаковые ключи и плейсхолдеры во всех 6 языках, нет русского текста, зашитого в интерфейс |
| `npm test` | Тесты (Vitest) |
| `npm run dist` | Сборка NSIS-инсталлятора в `release/` |

## Структура исходников

Весь код — TypeScript. Серверная часть живёт в `server/ts/`, процессы Electron — в `electron/ts/`, служебные скрипты — в `scripts/ts/`; фронтенд — в `src/`. Перед запуском/тестами `npm run compile` собирает их в соседние `*.js` (они в `.gitignore`), поэтому `package.json → main`, `node server/index.js` и `require("../server")` работают как раньше.

## Технологии

Electron · React 18 · TypeScript · Vite · Express · SQLite (better-sqlite3) · ONNX Runtime · Vitest

Стартовый бандл интерфейса — около 0,5 МБ (страницы и тяжёлые библиотеки — графики, редактор, формулы — грузятся по требованию, словари языков тоже).

## Где хранятся данные

Всё — в папке `storage\` рядом с программой. Она не удаляется при деинсталляции и не
затрагивается обновлениями: настройки, ключи, скачанные модели и файлы остаются на месте.

Основная база — SQLite (`storage\data.db`, режим WAL): версия схемы хранится в `PRAGMA user_version`, миграции лежат в `server/ts/db.ts`, а на диск пишутся только изменённые строки. Старый `data.json` при первом запуске переносится автоматически и остаётся рядом как `data.json.migrated` (резервная копия). Бэкапы снимают консистентный снимок базы (`VACUUM INTO`). Дневник — это папка `storage\diary\` с файлами `ГГГГ-ММ-ДД.md`.

## Безопасность

- Локальный API слушает только `127.0.0.1`, каждый запрос (включая ресурсы `<img>`/`<video>`) требует сессионный токен; токен сравнивается за постоянное время и передаётся в окно через IPC, а не через argv/файл.
- Окно приложения работает в песочнице Chromium (`sandbox: true`), внешние процессы запускаются через `execFile` без shell.
- Жёсткий CSP в Electron-окне: инлайн-скрипты и внешние загрузки запрещены.
- Секреты шифруются через Electron safeStorage (DPAPI) с фолбэком на AES-256-GCM.

## Веб-компаньон: безопасность

Основной API приложения слушает только `127.0.0.1` и в сеть не выходит. Компаньон — **отдельный** маленький сервер, который поднимается лишь после включения в *Настройки → Веб-компаньон*:

- принимает запросы только из частных сетей (192.168.x.x, 10.x.x.x, 172.16–31.x.x, link-local) — проброс порта на роутере не поможет;
- сверяет заголовок `Host` с IP-адресом (защита от DNS rebinding) и не использует cookie (защита от CSRF — токен идёт в заголовке);
- пускает на телефон только после ввода одноразового 6-значного кода из приложения (код живёт 5 минут, перебор ограничен по IP и в целом);
- хранит лишь SHA-256 токенов; устройство отзывается одним нажатием;
- отдаёт только заметки, задачи, «входящие» и состояние плеера. Менеджер паролей, ключи, настройки и файловая система недоступны;
- принимает файлы до 200 МБ в `storage\companion\inbox\` и отклоняет исполняемые типы (`.exe`, `.bat`, `.ps1`, `.js` и т. п.).

## Подпись кода

Установщик пока не подписан (поэтому SmartScreen предупреждает). Подпись встроена в сборку и включается секретами репозитория — без них всё работает как раньше:

1. **Azure Trusted Signing** (рекомендуется, не нужен файл сертификата): заведите аккаунт и профиль подписи, служебный принципал с ролью *Trusted Signing Certificate Profile Signer*, затем добавьте секреты `AZURE_TENANT_ID`, `AZURE_CLIENT_ID`, `AZURE_CLIENT_SECRET` и переменные репозитория `AZURE_TS_ENDPOINT`, `AZURE_TS_ACCOUNT`, `AZURE_TS_PROFILE`.
2. **Обычный сертификат `.pfx`**: переменные окружения `WIN_CSC_FILE` и `WIN_CSC_KEY_PASSWORD`.

Файлы подписываются внутри `electron-builder` (`win.sign` → `scripts/ts/sign.ts`), поэтому хэши в `latest.yml` и автообновление остаются корректными.

## CI

- `ci.yml` — на каждый push и pull request: typecheck, lint, проверка кодировки, полнота переводов, тесты и сборка фронта.
- `release.yml` — на тег `v*`: те же проверки, сборка и публикация установщика.
